# 多周期 CPU 设计记录（v2.0 —— 4 状态机版）

> 版本：2026-08-10  ·  在 v1.0 基础上重构  ·  已通过 iverilog 仿真验证
> v1.0 见 [single_cpu_design_v1.0.md](single_cpu_design_v1.0.md)

## 1. 这一版改了什么

v1.0 的单周期回写有个致命缺陷：**指令字段抓取的时机错开，永远凑不齐同一条指令的完整操作数**。

v2.0 的核心改动：用**独立的 4 状态状态机**把一条指令的执行拆成 4 拍（FET1 → FET2 → OPR → WRT），
并引入 **IR（指令寄存器）** 在 OPR 拍锁存完整指令快照，从根上消灭了字段错位和同沿竞争。

- 指令格式从"8 位一条"改为**变长：每条指令 2 个字节**（opcode 字节 + operand 字节）
- opcode 从 2 位扩到 **3 位**（最多 8 条指令），目前实现 ADDI、ADD，预留 SUB

## 2. 总体架构

```
               ┌────────┐
 clk ────────▶ │   fsm  │──▶ stage[1:0]（FET1/FET2/OPR/WRT）
 rst ────────▶ │ (状态机)│
               └────────┘
                    │ stage
        ┌───────────┼───────────────┬──────────────┐
        ▼           ▼               ▼              ▼
     ┌──────┐   ┌────────┐   ┌──────────┐   ┌──────────┐
     │  pc  │──▶│ ins_rom│──▶│ decoder  │──▶│   ir     │
     └──────┘   └────────┘   └──────────┘   └────┬─────┘
       ▲                                          │ opcode/addr1/addr2/waddr
       │（FET1/FET2 拍加 1）                      ▼
                                                  ┌──────────┐   ┌─────┐
                                                  │  reg_f   │──▶│ alu │
                                                  └────┬─────┘   └──┬──┘
                                                       │wdata=alu_res
                                                       ▼
                                                   写回（WRT 拍）
```

**数据流一句话**：decoder 分两拍抓指令字段 → IR 在 OPR 拍锁存成完整快照 → reg_f/alu 只认 IR →
WRT 拍把结果写回。

## 3. 指令集设计（变长，2 字节/条）

**字节 0（opcode 字节）：**

```
    7 6 5   4 3 2    1 0
  ┌───────┐ ┌─────┐ ┌───┐
  │ opcode│ │ addr1│ │00 │    // [1:0]=00 标记"这是 opcode 字节"
  └───────┘ └─────┘ └───┘
```

**字节 1（operand 字节）：**

```
    7 6 5   4 3 2    1 0
  ┌───────┐ ┌─────┐ ┌───┐
  │ addr2 │ │ addr3│ │11 │    // [1:0]=11 标记"这是 operand 字节"
  └───────┘ └─────┘ └───┘
```

| 字段 | 位 | 含义 |
|------|-----|------|
| opcode | 字节0 [7:5] | 操作码，3 位 |
| addr1 | 字节0 [4:2] | 源寄存器 1（读口1） |
| addr2 | 字节1 [7:5] | 源寄存器 2（读口2），ADDI 强制为 0 |
| addr3 | 字节1 [4:2] | 目标寄存器（写口） |

**已实现 opcode：**

| 助记符 | 编码 | 行为 |
|--------|------|------|
| ADDI | 000 | addr2 置 0（立即数模式占位，暂用 r0 当第二操作数） |
| ADD | 001 | 双寄存器相加 |
| SUB | 010 | 预留，ALU 未实现 |

## 4. 状态机设计（fsm.v）

```
        ┌──────────┐
        ▼          │
     ┌──────┐   ┌──────┐
 FET1│ 00   │──▶│ FET2 │
 └──────┘   └──┬───┘
      ▲        │
      │     ┌──▼───┐
      │     │ OPR  │ 10
      │     └──┬───┘
      │        ▼
      │     ┌──────┐
      │   ┌─│ WRT  │ 11
      └───┘ └──────┘
```

| 状态 | 编码 | PC | decoder | IR | reg_f |
|------|------|-----|---------|----|-------|
| FET1 | 00 | +1 | 抓 opcode、addr1（需字节0 [1:0]=00） | — | — |
| FET2 | 01 | +1 | 抓 addr2、addr3（需字节1 [1:0]=11） | — | — |
| OPR | 10 | 保持 | — | **锁存完整指令** | 读口稳定供 ALU |
| WRT | 11 | 保持 | — | — | **写回** regs[waddr]<=wdata |

- 复位 → FET1
- 复位时 PC=0；**PC 只在 FET1/FET2 两拍 +1**，OPR/WRT 保持

## 5. 各模块说明

### fsm.v —— 4 状态状态机
`output reg [1:0] stage`，纯状态推进，无其他逻辑。

### pc.v —— 程序计数器
- 复位 → 0
- `stage==FET1 || stage==FET2` 时 +1，其余保持
- 配合 2 字节指令：FET1 指向 opcode 字节，FET2 指向 operand 字节

### ins_rom.v —— 指令存储器（256 字节）
组合读 `inst = mem[addr]`。当前程序：

```verilog
mem[0] = 8'b000_000_00;  // 指令1 opcode字节：ADDI, addr1=r0
mem[1] = 8'b011_001_11;  // 指令1 operand字节：addr2=0(ADDI), addr3=r1
mem[2] = 8'b001_001_00;  // 指令2 opcode字节：ADD,  addr1=r1
mem[3] = 8'b001_010_11;  // 指令2 operand字节：addr2=r1, addr3=r2
```

即：`r1 = r0 + r0`；`r2 = r1 + r1`

### decoder.v —— 指令译码
- 标准异步复位：`posedge clk or posedge rst`，复位时四个字段全部清 0
- FET1 拍：`stage==00 && inst[1:0]==00` → 抓 `opcode=inst[7:5]`、`addr1=inst[4:2]`
- FET2 拍：`stage==01 && inst[1:0]==11` → 抓 `addr2`（ADDI 置 0，否则取 inst[7:5]）、`addr3=inst[4:2]`
- 关键：分两拍抓取，字段各自稳定后才被 IR 读取
- 修复记录：曾因敏感表列 rst 但函数体不判 rst，报 `[Synth 8-91] ambiguous clock`；加复位分支后解决

### ir.v —— 指令寄存器
- `stage==OPR(10)` 时锁存 `{opcode, addr1, addr2, waddr}` 四个字段
- 这是本版的核心：**一个完整的指令快照**，之后 reg_f/alu 只认 IR，不再受 decoder 后续覆盖影响

### reg_f.v —— 寄存器堆（8 个 8 位寄存器）
- 组合读：`rs1=addr1`、`rs2=addr2`，`r0` 恒 0
- WRT 拍写回：`stage==11 && we && waddr!=0` 时 `regs[waddr] <= wdata`
- 初值：`regs[1]=5`，其余 0

### alu.v —— 运算单元
- 纯组合 `always @(*)`，`opr` 来自 IR.opcode
- ADDI/ADD → `a+b`；其余 → 0

### single_cpu_top.v —— 顶层
按架构图把 7 个模块连起来：`stage` 广播给 pc/decoder/ir/reg_f，
decoder 输出进 IR，IR 输出进 reg_f/alu，`alu_res` 回灌 reg_f.wdata。

## 6. 单指令 4 拍数据流

以指令 1（ADDI r1, r0, r0）为例：

| 拍 | stage | 发生的事 | IR 状态 |
|----|-------|---------|---------|
| 1 | FET1 | pc=0→1，decoder 抓 op=000, addr1=000 | 旧值 |
| 2 | FET2 | pc=1→2，decoder 抓 addr2=000, addr3=001 | 旧值 |
| 3 | OPR | **IR 锁存 op=000 a1=000 a2=000 w=001**；ALU 算 0+0=0 | 指令1完整 ✓ |
| 4 | WRT | regs[1] <= 0（沿后 r1 变 0） | 保持指令1 |

**为什么这样没有竞争**：OPR 拍时 decoder 四个字段都已稳定（opcode/addr1 早在 FET1 就抓好，
addr2/addr3 在 FET2 抓好，OPR 期间不变），IR 一拍锁存，杜绝了 v1.0 的"同沿读写在先"。

## 7. 仿真验证（iverilog）

波形逐帧核对，关键帧：

```
T=45000 | stage=10 | ir(op=000 a1=000 a2=000 w=001)   ← 指令1完整进IR，字段不混
T=55000 | stage=11 | r1=5 → 沿后 r1=0                   ← WRT 写回生效
T=75000 | stage=01 | dec(op=001 a1=001 a2=001 a3=010)  ← 指令2译码完整
T=85000 | stage=10 | ir(op=001 a1=001 a2=001 w=010)    ← 指令2完整进IR
T=95000 | stage=11 | r2=0 → 沿后 r2=0                   ← 指令2写回
```

**结论**：4 状态机 + IR 消除了字段错位、act 错位、同沿竞争三个 v1.0 遗留问题，时序成立。

> 注：两条指令结果都是 0，因为程序没把 `regs[1]=5` 当源操作数。想看到 5→10 的流动，
> 把程序改成 `ADD r2, r1, r1` 放第一条即可（见 v2.0 末尾调试建议）。

## 8. 已知问题 / 限制

| # | 问题 | 影响 | 状态 |
|---|------|------|------|
| 1 | decoder 无 if(rst) 守卫 | 复位期间捕获 mem[0] | 已修复（异步复位，字段清 0） |
| 2 | `we` 硬编码 1 | 所有指令都写，暂无跳转/比较类指令 | 留待控制信号扩展 |
| 3 | 程序跑完进 X | 重复执行最后一条 | 填 NOP 或提前停 |
| 4 | ADDI 无立即数字段 | addr2 恒 0 | 需设计立即数字段 |
| 5 | SUB 只定义了编码 | ALU 未实现 | 待加 |
| 6 | 每条指令固定 4 拍 | PC 只能顺序 | 待加跳转 |
