# 流水线 CPU 设计记录（v6.4 —— UART 发送 + 内存映射 IO + busy 状态轮询）

> 版本：2026-08-13  ·  在 v6.3 的访存指令 + 寄存器堆读路径重构基础上，
> **新增 uart_tx 串口发送器**，把 **SB 复用为"端口写"**（按地址分流：RAM / UART），
> 并把 **uart_tx.busy 状态镜像到 regs[255]** 供程序用 `LBNE r255,r0` 自旋轮询。
> 指令集仍是 **29 条，没有为 UART 新增任何指令**——IO 走内存映射端口，时序协议全在程序里。
> v6.3 见 [single_cpu_design_v6.3.md](single_cpu_design_v6.3.md)

## 0. 版本说明

架构仍是 v6.3 的 4 级流水（IF/ID/EX/WB 每拍推进）+ EX 级旁路转发 + 栈保护 + 访存。本次核心是**给 CPU 开了个"嘴"**：

| 维度 | v6.3 | v6.4（当前代码） |
|------|------|------------------|
| IO 外设 | 无（只访存，无外部交互） | **uart_tx 串口发送器**（115200 波特、8N1） |
| 端口写 | SB 只写 data_ram | **SB 按地址分流**：`≤8191` 写 data_ram；`0x2000–0x3FFF`（bit13=1）→ 发 UART |
| busy 查询 | 无 | **regs[255] = busy 镜像**（reg_f 每拍刷新），程序 `LBNE r255,r0` 自旋轮询 |
| 指令集 | 29 条 | **29 条（不变）**——IO 不加指令，复用 LBU/SB 的访存编码 |
| 顶层端口 | 无对外输出 | 新增 **`output tx`** |
| 接收方向 | — | **uart_rx 占位（空壳）**，未实现 |
| data_ram | 手写同步读模板（推断） | **强制 `ram_style="block"`**（上板用 BRAM，见 §10 已知限制） |

## 1. 总体架构（v6.3 + UART 发送通路）

```
clk/rst ─▶ fsm ── stage（1-bit：EXE/IDLE）──▶ 广播到 if_reg / id_reg / wr_reg / pc

  ┌──────── IF ────────┬──────── ID ────────┬──────── EX ────────┬──── WB ────────┐
  │ pc ──▶ ins_rom     │ decoder（组合译码） │ alu（组合运算）     │ wr_reg          │
  │        │ 4B 窗口   │   reg_f 读(组合)    │   ▲                │  ▾ 下一拍写回    │
  │        ▼           │   + 两层前送        │   └─ result_last ──┘  reg_f 写        │
  │      if_reg ──────▶│   + j_flag 栈保护   │   └─ ram_data（LBU 旁路）               │
  │        （取指寄存器） │   + addr_ram/ram_flag│                                        │
  └──────────────────────────────────────────────────────────────────────────────┘
        data_ram ◀── decoder（addr_ram / wdata / ram_flag[0]=SB 写使能，ID 级落盘）
        data_ram ──▶ alu（ram_data，LBU 同步读出后 EX 级可用）
        uart_tx ◀── decoder（tx_en，地址分流）/ reg_f（rr_wdata = 待发字节）
        uart_tx ──▶ busy ──▶ reg_f（regs[255]）──▶ decoder（r_ram=255 组合读）──▶ LBNE 轮询
```

**相对 v6.3 新增/改动的结构**：
1. **uart_tx**：状态机式串口发送器。`tx_en` 拉高一拍即锁存 `tx_data` 开始发帧；
   `busy` 在整帧（4340 拍）期间保持 1，帧完自动归 0。
2. **SB 端口分流**（decoder）：SB 的地址字段按值域分流——`≤8191` 走 data_ram（`ram_flag[0]=1`）；
   `0x2000–0x3FFF`（bit13=1）→ `tx_en=1` 触发 uart_tx 发送。**同一条 SB 指令，地址决定它是"存内存"还是"发串口"**。
3. **busy 状态寄存器**（reg_f）：`regs[255] <= (busy)?1:0` 每拍刷新。CPU 用 `LBNE r255,r0`
   判 busy 是否为 1——**这是本设计的"状态查询"机制**：硬件只把状态映射成一个寄存器，轮询循环是纯程序。

## 2. 运行控制：1-bit stage（EXE/IDLE）

与 v6.3 相同，未变：fsm 退化为运行/停机锁存，`rst → EXE`、`frz（HALT 译码）→ IDLE`、否则 EXE。
所有流水寄存器只在 `stage == EXE` 推进。

## 3. 指令集（6-bit opcode，29 条，未变）

**本版没有新增指令**。UART 发送完全复用 SB：地址落在 UART 端口区间就当 IO 写。指令表沿用 v6.3
（LBU=01_1100 / SB=01_1101 两条访存指令），这里只列 SB 在本版的新语义，完整表见 v6.3 §3。

## 4. 指令编码与 IO 地址空间（v6.4 核心）

### 4.1 地址空间划分

SB（以及 LBU，但本版 LBU 未接 UART 读）的 16 位地址字段 `addr_ram = inst_raw[15:0]` 按值域分流：

| 地址区间（inst_raw[15:0]） | 含义 | 去向 |
|---------------------------|------|------|
| `0x0000 – 0x1FFF`（≤ 8191） | data_ram 数据地址 | 写：data_ram；读：LBU 旁路进 alu |
| `0x2000 – 0x3FFF`（bit13=1） | **UART 发送端口** | SB → `tx_en` 触发 uart_tx |
| `0x4000 +`（bit14/15 置位） | 未定义 | decoder 走 else，`tx_en` 依 bit13 而定（黑洞，写入丢弃） |

decoder 的分流逻辑（SB 分支）：
```verilog
SB: begin
    addr_dr12[23:16] = inst_raw[23:16];        // 源寄存器（v6.4 修复，见 §9 调试记录 2）
    addr_ram = inst_raw[15:0];
    if (inst_raw[15:0] <= 8191) ram_flag[0] = 1'b1;              // data_ram 写
    else tx_en = (inst_raw[13] == 1'b1) ? 1'b1 : 1'b0;           // UART 发
end
```

**与 v6.3 文档的差异（请确认）**：v6.3 文档 §4 写 `addr_ram = inst_raw[15:3]`（地址取 16 位端口字段的
**高 13 位**，byte3 低 3 位丢弃）；当前实现 decoder 输出 `addr_ram = inst_raw[15:0]` 全量、data_ram 取
**低 13 位** `[12:0]`。两者对同一字节流的 13 位地址含义不同（例：`77 01 00 28` → 按 v6.3 文档是地址 5，
按当前实现是地址 0x28=40）。v6.3 的 load/store 测试读写同址所以自洽通过，未暴露。**本文档以当前代码为准**。

### 4.2 SB 4B 布局（本版复用）

```
SB（4B，byte0=0x77）：
  byte0 = opcode[5:0] | len=11
  byte1 = rs[7:0]                （数据源寄存器：值为待发字节 / 待存字节）
  byte2:byte3 = 16 位地址字段     （低 13 位进 data_ram；bit13=1 即 UART 口）
```

例如 `77 01 20 00`：byte1=01（源 r1），byte2:byte3=0x2000（bit13=1 → **发送** r1 的值）。

## 5. 流水线机制（UART 数据通路）

基础时序（if_reg posedge C 锁存 → C+1 id_reg + pc 控制流 → C+2 wr_reg → C+3 写回）与 v6.3 相同。

### 5.1 UART 写方向（SB → uart_tx）

- **ID 级**：decoder 组合输出 `tx_en`（地址分流判出）+ `rr_wdata`（源寄存器值，含两层前送）。
- **同一拍 posedge**：uart_tx 在 `!busy && tx_en` 时锁存 `tx_data`、`tx<=0`（起始位）、`busy<=1`。
- **后续 4340 拍**：uart_tx 按 MCNT 节拍逐位移出（§5.2），CPU 此时可继续跑下一条指令。

### 5.2 uart_tx 帧时序

```
波特率 115200，50MHz → MCNT = 50000000/115200 = 434（拍/bit）
帧 = 起始(0) + 8 数据位(LSB-first) + 停止(1) = 10 bit = 4340 拍 = 86.8µs
```

```verilog
if (!busy && tx_en) begin          // 触发：锁存 + 拉起始位 + 置忙
    busy <= 1'b1;  tx_data_buf <= tx_data;  bit_cnt <= 0;  clk_cnt <= 0;  tx <= 1'b0;
end
else if (busy) begin
    if (clk_cnt < MCNT-1) clk_cnt <= clk_cnt + 1;
    else begin
        clk_cnt <= 0;
        if (bit_cnt <= 4'd7)      // 数据位 0..7
            {tx <= tx_data_buf[0]; tx_data_buf <= {1'b0, tx_data_buf[7:1]}; bit_cnt++;}
        else if (bit_cnt == 4'd8) // 停止位
            tx <= 1'b1; bit_cnt++;
        else busy <= 1'b0;        // 帧完，忙清除
    end
end
```

**停止位是 v6.3 遗留 bug 的修复点**（调试记录见 v6.4 §9 / 会话记录）：原实现 `bit_cnt <= 8` 在
第 8 位结束时把已移空的 `tx_data_buf[0]=0` 锁到 tx 上，停止位变低电平；修复为第 8 位后单独
`tx<=1` 拉高，第 9 拍才清 busy。

### 5.3 busy 状态轮询（regs[255] 镜像）

```verilog
// reg_f：每拍刷新
regs[255] <= (busy) ? 8'b1 : 8'b0;
// 程序：发送前自旋，等 busy 归零
LBNE r255, r0, 回跳   // busy==1 则回跳（继续等）；busy==0 顺序执行 SB
SB  r1, 0x2000        // 发送
```

- **为什么映射成寄存器而非加状态指令**：不加指令、不加译码，CPU 用**现有 LBNE + r255** 就能查询外设状态。
  这是内存映射 IO + 状态寄存器的最简实现，硬件代价只有 reg_f 一行。
- **副作用**：r255 被 busy 占用，用户程序不可用作普通寄存器（见 §10 已知限制）。
- **轮询是纯软件**：硬件只提供"可写端口 + 可查状态"，协议时序（何时发、发几字节、帧间等待）全在程序里。

### 5.4 SB 源寄存器传递（本版修复，见调试记录 2）

decoder 的 SB 分支补 `addr_dr12[23:16] = inst_raw[23:16]`——SB 才能从 reg_f 读到正确的源寄存器值。
v6.3 遗漏此行，SB 恒读 regs[0]=0，全靠"紧跟 ADDI 后的前送"掩盖；UART 轮询场景（发送与 ADDI 被
自旋隔开一拍以上）暴露字节 2、3 发送 0x00。修复后源寄存器正常传递。

## 6. 当前程序（UART 轮询发送测试，ins_rom.hex）

```
@0000
07 01 00 48 63 08 FF 00 77 01 20 00      ; 发送 'H'(0x48)
07 01 00 69 63 08 FF 00 77 01 20 00      ; 发送 'i'(0x69)
07 01 00 21 63 08 FF 00 77 01 20 00      ; 发送 '!'(0x21)
00                                        ; HALT
```

| 地址 | 指令 | 作用 |
|------|------|------|
| 0x00 | ADDI r1,r0,0x48 | 准备待发字节 'H' |
| 0x04 | LBNE r255,r0,回跳 | **轮询**：busy=1 则回 0x00 重跑（重算 r1 无害）；busy=0 顺序执行 |
| 0x08 | SB r1,0x2000 | **发送** r1（地址 bit13=1 → uart_tx） |
| 0x0C–0x20 | 同上 ×2 | 发 'i'、'!' |
| 0x24 | HALT | 收尾 |

**LBNE 后向跳转语义**（pc.v）：`new_pc = (分支地址 + 分支指令长度) − bytmov`。
0x04 处的 LBNE 是 4B 指令，EX 级 pc_addr = 0x08，要跳回 0x00 需 `bytmov = 0x08 − 0x00 = 8`（byte1=0x08）。
（第一次写错为 4 导致跳过头，见调试记录 3。）

### 7.2 CPU→UART 整机集成测试（uart_poll_tb.v）

tb 内建 **UART 接收模型**（检测起始位下降沿 → 按 MCNT 中点采样 start/8数据/stop），载入 §6 程序，

```
RX @82570000 0x48 = H
RX @169450000 0x69 = i
RX @256330000 0x21 = !

===== ALL TESTS PASSED =====
```

- 三帧间隔精确 86.88µs（= 一帧时长 4340 拍），证明 **busy 轮询真正生效**（发完一拍才发下一拍）、没丢字节。
- 每帧起始/8 数据/停止位全部正确，uart_tx 时序无误。

## 8. 综合与时序（Vivado，xc7z010clg400-1，50MHz / 20ns）

实现后时序报告：

| 时序 | 余量 | 说明 |
|------|------|------|
| 建立 Setup | **3.108 ns** | 关键路径约 16.9ns，健康 |
| 保持 Hold | **0.076 ns** | 过线但贴边（见下） |
| 脉宽 Pulse | **8.750 ns** | 时钟干净 |

**hold 0.076ns 为什么最紧**：wr_reg→reg_f 写回是设计里逻辑深度最小的路径之一（纯 FF 直连写端口，
`rd_data <= result_in` 无组合逻辑），hold 对**最短路径**最苛刻（数据冲太快 + 时钟偏斜），其余路径有
组合逻辑垫着反而宽裕（0.1ns 以上）。这是物理规律，不是缺陷；0.076 > 0 即满足保持时间，可正常上板。

**上板注意**：`timing.xdc` 目前只有 `create_clock -period 20.000 -name sys_clk [get_ports clk]`，
**尚未绑引脚**。上板前需补：clk 实际时钟源引脚、tx 的 UART TX 引脚、rst 复位引脚。
**板验状态：待验证**（综合/实现通过后烧板，串口助手 115200 8N1，先开助手再按 rst）。

## 9. 调试记录

### 调试记录 1：顶层 tx_en 悬空 → 整机 TIMEOUT

- **现象**：首次整机测试 HALT 但 rx_cnt=0，UART 永不发
- **根因**：single_cpu_top 例化 uart_tx 传了 `.tx_en(tx_en)`，但顶层 wire 没人赋值（悬空）
- **修复**：tx_en 改由 decoder 内按地址分流生成（§4.1），顶层移除临时 `assign`

### 调试记录 2：字节 2、3 发送 0x00（decoder SB 缺源寄存器传递）

- **现象**：补上 tx_en 后，字节 1 正确（0x48 'H'），字节 2、3 都发 0x00
- **根因**：decoder 的 SB 分支没有 `addr_dr12[23:16] = inst_raw[23:16]`，reg_f 按 r_ram=0 读
  regs[0]=0 → wdata=0。字节 1 是紧跟 ADDI 靠 `result_last` 前送掩盖；轮询自旋把 ADDI 和 SB 隔开
  一拍以上，前送失效暴露
- **修复**：SB 分支补一行 `addr_dr12[23:16] = inst_raw[23:16];`
- **验证**：修复后第 2 帧 rr_w=105（0x69），正确

### 调试记录 3：LBNE 后向跳转 bytmov 偏移算错

- **现象**：字节 2 轮询循环失控 / 跳转目标错
- **根因**：pc.v 分支用 EX 级 `pc_addr` 计算 `new_pc = pc_addr ± bytmov`，而 EX 级 pc_addr
  = **分支地址 + 分支指令长度**（4B 分支 → +4）。故后向跳转 `bytmov = (分支地址 + 4) − 目标`
- **修复**：hex 里 `63 04` → `63 08`（0x08 − 0 = 8）
- **教训**：分支偏移要按"分支指令之后的地址"算，不是分支自身地址

### 调试记录 4：uart_tx 停止位低电平（v6.3 遗留，用户自修）

- **现象**：停止位被采样为 0（帧错误）
- **根因**：原 `if (bit_cnt <= 8)` 在第 8 位结束时把已移空的 `tx_data_buf[0]`（=0）锁到 tx
- **修复**：第 8 位后单独 `tx <= 1`，第 9 拍清 busy（见 §5.2 代码）

## 11. 已知限制

| 限制 | 说明 |
|------|------|
| **uart_rx 未实现** | `uart_rx.v` 是空壳（无端口无逻辑），串口只能发不能收；回环/接收需先补 rx |
| **r255 被 busy 占用** | reg_f 每拍写 regs[255]，用户程序用 255 号寄存器会被 busy 覆盖 |
| **UART 口只判 bit13** | 0x2000–0x3FFF 视为发送口；0x4000+（bit14/15）未定义，写入丢弃（黑洞） |
| **地址编码文档/代码差异** | v6.3 文档写 `inst_raw[15:3]`（高 13 位），当前实现 `inst_raw[15:0]` 取低 13 位进 RAM（§4.1），以当前代码为准 |
| data_ram 强制 block | BRAM **无复位、上电为 x**，`initial` 清零只在仿真有效；程序应避免读未初始化单元 |
| 发送不排队 | busy 期间 `tx_en` 静默屏蔽（丢字节），必须程序轮询保证一拍一发 |
| 只发一轮 | 当前测试程序发 3 字符后 HALT；上板想持续看到需改死循环重发（hex 可改） |
| 上板引脚未约束 | timing.xdc 仅时钟约束，需补 clk/tx/rst 引脚绑定 |
| 其余 v6.3 限制沿用 | 访存地址 13 位、load-use 靠旁路、条件分支 1 拍气泡、栈深 255 等，见 v6.3 §10 |
