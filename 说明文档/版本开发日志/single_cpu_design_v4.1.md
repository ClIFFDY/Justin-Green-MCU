# 多周期 CPU 设计记录（v4.1 —— 指令集扩展：10 → 19 条，架构不变）

> 版本：2026-08-11  ·  在 v4.0 架构基础上**只扩展指令集**（状态机 / opcode 宽度 / 寄存器宽度 / 指令编码格式均未动）
> v4.0 见 [single_cpu_design_v4.0.md](single_cpu_design_v4.0.md)，v3.0 见 [single_cpu_design_v3.0.md](single_cpu_design_v3.0.md)，
> v2.1 见 [single_cpu_design_v2.1.md](single_cpu_design_v2.1.md)，v2.0 见 [single_cpu_design_v2.0.md](single_cpu_design_v2.0.md)，v1.0 见 [single_cpu_design_v1.0.md](single_cpu_design_v1.0.md)

## 0. 版本说明

沿用 v3.0 第 0 节标准——架构没变算小版本，架构变了算大版本，编码不兼容算重写。
v4.0 之后架构未动（4 状态 FSM、6-bit opcode、4 字节变长标签编码、64 个寄存器、
bytnum 延迟返回机制），仅新增 9 条 ALU 指令并扩展 reg_f 的初始化，故记 **v4.1**。

| 维度 | v4.0 | v4.1 |
|------|------|------|
| opcode | 6-bit（10 条） | 6-bit（19 条），00_0000–01_0010 连续 |
| reg_f | initial 只清 regs[0..7] | for 循环清全部 64 个 |
| 新指令 | — | ANDI/ORI/XORI/SLL/SRL/SLLI/SRLI/SLTU/SLTIU（9 条） |

编码方式未变，v4.0 的 10 条编码原样保留，程序码完全兼容；新增指令填进空位后
紧凑重排（见 §8），故不算 v5.0。

## 1. FSM（4 状态 + 变长取指 + frz 冻结，与 v4.0 相同）

```
IDLE(000) → FET(001) → OPR(010) → WRT(011) → FET …
    ↑
    └──────── HALT 时 frz=1，OPR 拍回 IDLE 并关写（we=0）────────
```

| 状态 | 动作 |
|------|------|
| IDLE | `!frz` 时 we=1、进 FET（HALT 后停在这里，we=0） |
| FET | 取当前字节；`inst_raw[1:0]!=2'b11` 就留在 FET 继续取；读到标签 11 → 进 OPR |
| OPR | IR 快照译码结果；遇 frz → 回 IDLE、we=0；否则进 WRT |
| WRT | 寄存器写回；JMP 的延迟返回在这里触发 |

变长取指：4 字节指令走 4 拍 FET（opcode / rd / addr1 / imm 各一字节），PC 每拍 +1。
本版所有非 HALT 指令仍都是 4 字节。

## 2. 指令集（6-bit opcode，19 条）

| 编码 | 助记符 | 行为 | 归属 |
|------|--------|------|------|
| 00_0000 | HALT | 冻结整机（frz=1） | 控制 |
| 00_0001 | ADDI | rd = rs1 + imm8 | ALU |
| 00_0010 | ADD  | rd = rs1 + rs2 | ALU |
| 00_0011 | SUBI | rd = rs1 - imm8 | ALU |
| 00_0100 | SUB  | rd = rs1 - rs2 | ALU |
| 00_0101 | AND  | rd = rs1 & rs2 | ALU |
| 00_0110 | OR   | rd = rs1 \| rs2 | ALU |
| 00_0111 | XOR  | rd = rs1 ^ rs2 | ALU |
| 00_1000 | LJMP | 后向跳转（opcode[0]=0 → addr − bytmov） | 控制流 |
| 00_1001 | RJMP | 前向跳转（opcode[0]=1 → addr + bytmov） | 控制流 |
| 00_1010 | ANDI | rd = rs1 & imm8 | ALU |
| 00_1011 | ORI  | rd = rs1 \| imm8 | ALU |
| 00_1100 | XORI | rd = rs1 ^ imm8 | ALU |
| 00_1101 | SLL  | rd = rs1 << rs2 | ALU |
| 00_1110 | SRL  | rd = rs1 >> rs2 | ALU |
| 00_1111 | SLLI | rd = rs1 << imm8 | ALU |
| 01_0000 | SRLI | rd = rs1 >> imm8 | ALU |
| 01_0001 | SLTU | rd = (rs1 < rs2) ? 1 : 0 | ALU |
| 01_0010 | SLTIU | rd = (rs1 < imm8) ? 1 : 0 | ALU |

- 19 条编码从 00_0000 到 01_0010 **连续无空位**（SRA/SRAI 删掉后紧凑重排，见 §8）
- 寄存器 6-bit 地址 → 64 个；r0 恒读 0、写入被跳过
- imm8 取字节 `inst_raw[7:2]`（6-bit 值），零扩展成 8-bit，范围 0~63；SLTU/SLTIU 是无符号比较，imm8 也按无符号看待
- 移位量：SLL/SRL 用 rs2（8-bit），SLLI/SRLI 用 imm8（8-bit）——寄存器 `regs[0]` 恒 0，r0 作移位量即恒不移

## 3. 指令编码：4 字节变长标签格式（tag-11 分组更新）

每个字节的 `[1:0]` 是标签，指示这个字节装什么：

| 标签 | ALU 指令 | JMP 指令 |
|------|----------|----------|
| 00 | opcode = [7:2] | opcode = [7:2] |
| 01 | rd = [7:2] | bytins_h = [7:2] |
| 10 | addr1 = [7:2] | bytins = {bytins_h, [7:6]}；bytmov_h = [5:2] |
| 11 | 见下方分组 | bytmov = {bytmov_h, [7:4]}；jmpret = [3:2] |

**标签 11 的字节按 opcode 分组**（decoder.v 里对应三个 case 分支）：

| 分组 | 指令 | byte3[7:2] 装什么 |
|------|------|-------------------|
| 寄存器-寄存器 | ADD SUB AND OR XOR SLL SRL SLTU | addr2 = [7:2]，imm8 = 0 |
| 立即数 | ADDI SUBI ANDI ORI XORI SLLI SRLI SLTIU | imm8 = [7:2]，addr2 = 0 |
| 跳转 | LJMP RJMP | bytmov = {bytmov_h, [7:4]}，jmpret = [3:2] |

一个 ALU 立即数指令的例子（`SRLI r13 = r1 >> 2`）：
```
byte0  010000_00   opcode = 01_0000（SRLI）
byte1  001101_01   rd     = 001101（r13）
byte2  000001_10   addr1  = 000001（r1）
byte3  000010_11   imm8   = 000010（= 2）
```

一个 ALU 寄存器-寄存器指令的例子（`SLTU r15 = (r1 < r2)`）：
```
byte0  010001_00   opcode = 01_0001（SLTU）
byte1  001111_01   rd     = 001111（r15）
byte2  000001_10   addr1  = 000001（r1）
byte3  000010_11   addr2  = 000010（r2）
```

## 4. LJMP / RJMP 执行机制（与 v4.0 完全相同）

字段、编码、执行时序、两条调试记录（bytnum 不递减、JMP 误写寄存器）全部沿用 v4.0 §4，
此处不重复，详见 [v4.0 §4](single_cpu_design_v4.0.md)。

## 5. HALT（frz 冻结，与 v4.0 相同）

- decoder 在 FET 拍读到标签 00 且 `opcode==HALT` → `frz <= 1`
- FSM 在 OPR 拍读到 frz → `stage <= IDLE, we <= 0`
- 之后停在 IDLE：PC 不动、不取指、不写寄存器，整机冻结

## 6. 当前程序（ins_rom.v，19 条指令集的 ALU 覆盖测试，14 条指令 + HALT）

操作数准备：r1 = 10（0b1010）、r2 = 3（0b0011），之后 12 条 ALU 指令各写一个目标寄存器。

| mem | 指令 | 编码（4 字节） | 期望 |
|-----|------|----------------|------|
| 0–3  | ADDI r1 = r1 + 10 | `000001_00 / 000001_01 / 000001_10 / 001010_11` | r1 = 10 |
| 4–7  | ADDI r2 = r2 + 3 | `000001_00 / 000010_01 / 000010_10 / 000011_11` | r2 = 3 |
| 8–11 | AND r3 = r1 & r2 | `000101_00 / 000011_01 / 000001_10 / 000010_11` | r3 = 10&3 = 2 |
| 12–15 | OR r4 = r1 \| r2 | `000110_00 / 000100_01 / 000001_10 / 000010_11` | r4 = 10\|3 = 11 |
| 16–19 | XOR r5 = r1 ^ r2 | `000111_00 / 000101_01 / 000001_10 / 000010_11` | r5 = 10^3 = 9 |
| 20–23 | ANDI r6 = r1 & 6 | `001010_00 / 000110_01 / 000001_10 / 000110_11` | r6 = 10&6 = 2 |
| 24–27 | ORI r7 = r1 \| 6 | `001011_00 / 000111_01 / 000001_10 / 000110_11` | r7 = 10\|6 = 14 |
| 28–31 | XORI r8 = r1 ^ 6 | `001100_00 / 001000_01 / 000001_10 / 000110_11` | r8 = 10^6 = 12 |
| 32–35 | SLL r9 = r1 << r2 | `001101_00 / 001001_01 / 000001_10 / 000010_11` | r9 = 10<<3 = 80 |
| 36–39 | SRL r10 = r1 >> r2 | `001110_00 / 001010_01 / 000001_10 / 000010_11` | r10 = 10>>3 = 1 |
| 40–43 | SLLI r12 = r1 << 3 | `001111_00 / 001100_01 / 000001_10 / 000011_11` | r12 = 10<<3 = 80 |
| 44–47 | SRLI r13 = r1 >> 2 | `010000_00 / 001101_01 / 000001_10 / 000010_11` | r13 = 10>>2 = 2 |
| 48–51 | SLTU r15 = (r1 < r2) | `010001_00 / 001111_01 / 000001_10 / 000010_11` | r15 = (10<3) = 0 |
| 52–55 | SLTIU r16 = (r1 < 12) | `010010_00 / 010000_01 / 000001_10 / 001100_11` | r16 = (10<12) = 1 |
| 56–59 | HALT | `000000_00 / 000000_01 / 000000_10 / 000000_11` | 冻结 |

> 说明：目标寄存器沿用 r11–r16 的连续排法，删掉 SRA/SRAI 后 r11、r14 空出来，
> 测试程序直接跳过它们（保持 0），不影响结果。r0 恒 0、r14 未用，都无需处理。

## 7. 仿真验证（iverilog，tb 在 #1250 处第二次复位测试重启，$finish #2500）

第一轮（r1=10, r2=3）：

| 时刻 | 事件 | 结果 |
|------|------|------|
| T≈110000 | 取完 16 条指令前全部 ALU 写回 | r1=10 r2=3 r3=2 r4=11 r5=9 r6=2 r7=14 r8=12 r9=80 r10=1 r11=0 r12=80 r13=2 r14=0 r15=0 r16=1 |
| T=915000 | HALT @mem[56] | stage=000、pc=60、we=0，整机冻结 ✓ |
| T=1250000 | **第二次复位（rst 拉高 20ns）** | pc→0，r1 保留 10（reg_f 无复位） |

第二轮（r1=20, r2=6，全部指令重跑一遍）：

| 指令 | 期望 | 实际 |
|------|------|------|
| AND r3 | 20&6 = 4 | r3=4 ✓ |
| OR r4 | 20\|6 = 22 | r4=22 ✓ |
| XOR r5 | 20^6 = 18 | r5=18 ✓ |
| ANDI r6 | 20&6 = 4 | r6=4 ✓ |
| ORI r7 | 20\|6 = 22 | r7=22 ✓ |
| XORI r8 | 20^6 = 18 | r8=18 ✓ |
| SLL r9 | 20<<6 = 1280 → 8bit 截断 = 0 | r9=0 ✓ |
| SRL r10 | 20>>6 = 0 | r10=0 ✓ |
| SLLI r12 | 20<<3 = 160 | r12=160 ✓ |
| SRLI r13 | 20>>2 = 5 | r13=5 ✓ |
| SLTU r15 | (20<6) = 0 | r15=0 ✓ |
| SLTIU r16 | (20<12) = 0 | r16=0 ✓ |

第二轮跑完再次冻结（T≈2150000，stage=000、pc=60），$finish 正常。

**验证结论**：19 条指令集里 12 条 ALU 指令两轮全部正确（含 8-bit 溢出截断）；
r11/r14 全程 0 确认无指令误写；HALT 冻结 + 复位重启正常。
reg_f 的 initial for 循环把 64 个寄存器在 t=0 全清，但 rst 仍不清寄存器（刻意保留）。

## 8. 相对 v4.0 的变化汇总

| # | 变化 | 状态 |
|---|------|------|
| 1 | 新增 9 条 ALU 指令（ANDI/ORI/XORI/SLL/SRL/SLLI/SRLI/SLTU/SLTIU） | 已实现并验证 |
| 2 | reg_f initial 扩为 for 循环清全部 64 个寄存器 | 已改 |
| 3 | SRA / SRAI 曾加入又删除（见下） | 已删除 |
| 4 | 删后紧凑重排，19 条编码 00_0000–01_0010 连续 | 已改并验证 |

SRA / SRAI 增删记录：一度加入算术右移，但因 alu.v 的操作数 `a` 为 `wire [7:0]`（无符号），
`a >>> b` 高位补 0，与 `>>` 行为相同，未实现真正的算术右移，故删除。真算术右移需
`$signed(a) >>> b` 或把 a 声明为 signed，暂不做。删后 SLLI/SRLI/SLTU/SLTIU 前移补齐空位。
