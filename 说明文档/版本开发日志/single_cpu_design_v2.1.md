# 多周期 CPU 设计记录（v2.1 —— 指令集扩展 + JMP）

> 版本：2026-08-10  ·  在 v2.0 基础上扩展指令集并加入第一条控制流指令 JMP
> v2.0 见 [single_cpu_design_v2.0.md](single_cpu_design_v2.0.md)，v1.0 见 [single_cpu_design_v1.0.md](single_cpu_design_v1.0.md)

## 0. 版本说明

架构未变——仍为 v2.0 的 4 状态机（FET1→FET2→OPR→WRT）+ IR 快照。本次仅扩展指令集
（3 条扩到 7 条，新增 AND/OR/XOR，SUB 补上 ALU 实现）并加入第一条控制流指令 JMP，
架构不变、能力增强，故记 **v2.1**。

## 1. 指令集（7/8，opcode 只剩 111 空着）

| 编码 | 助记符 | 行为 | 归属 |
|------|--------|------|------|
| 000 | ADDI | r3 = r1 + imm8（imm8 = byte1[7:5]） | ALU |
| 001 | ADD | r3 = r1 + r2 | ALU |
| 010 | SUB | r3 = r1 - r2 | ALU |
| 011 | AND | r3 = r1 & r2 | ALU |
| 100 | OR | r3 = r1 \| r2 | ALU |
| 101 | XOR | r3 = r1 ^ r2 | ALU |
| 110 | JMP | 跳转到目标地址 | 控制流 |

- v2.0 基础上新增：AND、OR、XOR、JMP；SUB 从"只定义编码"补上 ALU 运算
- 寄存器字段仍是 3 位（8 个寄存器），opcode 占 byte0[7:5]，字段布局没变

## 2. JMP 的编码（2 字节，复用变长格式）

```
byte0 = 110_ jmp[高3位] _00       // [1:0]=00 标记 opcode 字节
byte1 = jmp[低5位] _11            // [1:0]=11 标记 operand 字节
```

| 字段 | 位 | 含义 |
|------|-----|------|
| opcode | byte0[7:5] | 固定 110 |
| jmp_mes[高3位] | byte0[4:2] | 偏移量高 3 位（decoder 里 jmp_mes_h） |
| jmp_mes[低5位] | byte1[7:3] | 偏移量低 5 位 |
| jmp_mes[7] | — | **方向位：0=往回跳，1=往前跳** |
| 偏移量 | 2 × jmp_mes[6:0] | ×2 因为每条指令占 2 字节，所以偏移以"指令条数"为单位 |

例：`jmp_mes = 00000011 = 3`，方向 0（往回）→ 往回跳 `2×3 = 6` 字节 = 3 条指令。

## 3. JMP 的执行机制（pc.v 新增 jmped/nextadd）

JMP 不是在 OPR 拍"改完 PC 就完事"，而是用一个小状态机 `jmped` 配合 `nextadd` 收尾：

```
OPR 拍：遇到 opcode==110 →
    nextadd <= addr            // 记下返回地址（= JMP 地址+2，PC 此时已经取完 JMP 的两个字节）
    addr    <= 目标地址         // 真正跳过去
    jmped   <= 10
WRT 拍：case jmped
    10 → jmped <= 01           // 目标指令还在执行，等它
    01 → jmped <= 00, addr <= nextadd   // 目标指令写完，跳回返回地址
FET1/FET2：无条件 addr <= addr + 1      // 取指节奏和普通指令完全一致
```

**当前语义**：JMP = **"跳到目标 → 执行一条指令 → 跳回 nextadd"**。
不是永久跳转，类似一个"单指令的调用并返回"（没有栈，只支持跳过去跑一条）。
想做真正的循环/分支，需要再改造。

> 调试记录：初版把 `jmped` 处理放在 FET1 拍，会"憋住"地址，导致 FET2 拍 PC 还停在
> 目标地址、读到的是同一个 opcode 字节（[1:0]=00），operand 字节（[1:0]=11）被跳过，
> 目标指令操作数全丢。**把 `jmped` 挪到 WRT 拍后取指恢复正常**——FET1/FET2 无条件 +1，
> 目标指令两个字节能完整抓到。

## 4. 当前程序（ins_rom.v）

```verilog
mem[0] = 8'b000_001_00;  // ADDI r1 = r1 + 1
mem[1] = 8'b001_001_11;
mem[2] = 8'b001_001_00;  // ADD  r2 = r1 + r2
mem[3] = 8'b010_010_11;
mem[4] = 8'b110_000_00;  // JMP 往回 3 条指令
mem[5] = 8'b00011_0_11;  // jmp_mes = 3，方向回
mem[6] = 8'b011_011_00;  // AND  r4 = r3 & r2
mem[7] = 8'b010_100_11;
```

寄存器初值：r1=2，r2=3，r3=4（r0 恒读 0）。

## 5. 仿真验证（iverilog）

| 时刻 | 事件 | 结果 |
|------|------|------|
| T=55000 | ADDI r1 = r1+1 | r1: 2→3 ✓ |
| T=95000 | ADD r2 = r1+r2 | r2: 3+3=6 ✓ |
| T=125000 | JMP 触发（OPR） | nextadd=6，addr 跳到 0 |
| T=175000 | 跳回 0 后执行 ADDI | r1: 3+1=4 ✓ |
| T=215000 | 跳回 6 执行 AND | r4: 4&6=4 ✓ |

取指完整性确认：目标指令（ADDI@0）的 opcode 字节和 operand 字节都被正确抓进 IR，
说明 `jmped` 挪到 WRT 后取指不再错位。

## 6. 已知限制

| # | 问题 | 说明 |
|---|------|------|
| 1 | 不是真 HALT | 程序跑完进 X 内存，`jmped` 只在 JMP 内部转一圈 |
| 2 | JMP 只跳一条 | 无法做真正的循环/分支 |
| 3 | 无条件跳转 | 无 zero 标志/比较器，做不了 `if` |
| 4 | opcode 只剩 111 | 再加指令需重新设计编码 |
| 5 | we 硬编码 1 | 所有指令都写，JMP 靠 waddr=0 避开写寄存器 |
